== Colors ==
No violation found.
- static/registration/login.css :root defines exactly 3 custom properties
  (--uc-dark-teal, --uc-mid-blue, --uc-cyan) — within the stated 3-color limit.
- The linear-gradient in .container (teal -> mid-blue -> cyan, 135deg) is NOT a
  purple-to-blue gradient, so it does not match the specific pattern the
  checklist calls out. It is the project's documented brand identity (see the
  header comment in frontend/src/ui/theme.css: "Visual language adopted from
  the UrbanConnect brand exploration").
- No gradient buttons: .btn / button use solid var(--uc-dark-teal).
- No alternating background pattern.
NOT AUTO-CHANGED: frontend/src/ui/theme.css defines additional custom
properties beyond the 3 brand colors (--uc-bg, --uc-surface,
--uc-surface-raised, --uc-glass, --uc-text, --uc-text-muted, --uc-border,
--uc-info, --uc-error, --uc-success). These are semantic tokens derived from
the 3 brand colors (surfaces/text/feedback-state), not an unrelated palette,
and are consumed by ~15 component rules across the file (header, nav, buttons,
inputs, badges, table, focus states). Collapsing them to 3 raw colors would be
a high-risk, ambiguous change likely to break the whole design system —
flagged for manual review instead of auto-edited, per the "stop and list files
if ambiguous" rule.
